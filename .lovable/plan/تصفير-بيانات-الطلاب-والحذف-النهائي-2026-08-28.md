# تصفير بيانات الطلاب والحذف النهائي

## ما سيتم بناؤه

### 1. تصفير سجلات طالب واحد (من ملف الطالب)
زر «تصفير سجلات الطالب» داخل ملف الطالب (بجانب أدوات إدارة الحالة)، يحذف كل السجلات السابقة للطالب مع الإبقاء على بياناته الأساسية:
- الحضور والاستئذانات
- التسميع وسجلات الأخطاء
- اختبار السرد (المحاولات والنتائج ونتائج الاختبارات)
- مدارج (التقدم اليومي، اختبارات الأحزاب، الأخطاء، تغييرات المستوى)
- الخطط السنوية وتقدم الخطة
- الاختبارات والاختبارات الذكية ونتائج مواد البرامج
- التربوي (السجلات الأسبوعية، درجات الاختبارات، المحاولات، الاستبيانات)
- التلقين (الحضور، المناهج المرتبطة، الاختبارات)
- البرنامج الصيفي، الرحلات، النقاط، الأوسمة، الترشيحات، الباصات، سجل الحالة

يظهر مربع تأكيد يعرض عدد السجلات التي ستُحذف لكل نوع، ويطلب كتابة اسم الطالب للتأكيد.

### 2. تصفير جماعي (صفحة الأرشفة/الأدوات الإدارية)
أداة للإدارة تصفّر سجلات جميع الطلاب (نفس الأنواع أعلاه) مع:
- اختيار أنواع البيانات المطلوب تصفيرها (نفس نمط اختيار الأنواع في صفحة الأرشفة)
- معاينة أعداد السجلات قبل التنفيذ
- تأكيد بكتابة كلمة تأكيد
- تنبيه واضح أن العملية غير قابلة للاسترجاع، مع اقتراح تنفيذ الأرشفة أولاً

### 3. حذف نهائي للطالب من صفحة «الطلاب المنقطعون»
زر «حذف نهائي» لكل طالب في `/inactive-students`:
- حذف كامل للطالب وكل سجلاته المرتبطة (بدون إمكانية استرجاع)
- مربع تأكيد يوضح الأثر ويطلب كتابة اسم الطالب
- متاح للمدير والسكرتير فقط

## الصلاحيات
- المدير والسكرتير فقط لجميع العمليات الثلاث، على مستوى الواجهة وعلى مستوى قاعدة البيانات.
- إضافة صلاحيتين إلى إدارة الصلاحيات: `purge_student_data` (تصفير السجلات) و`delete_student_permanently` (الحذف النهائي).

## تفاصيل تقنية
- إنشاء دالتين `SECURITY DEFINER` في قاعدة البيانات:
  - `purge_student_records(_student_id uuid, _tables text[] default null)` — تحذف سجلات الطالب من الجداول المحددة وتُرجع عدد المحذوف لكل جدول.
  - `purge_all_student_records(_tables text[])` — نفس المنطق لكل الطلاب.
  - `delete_student_permanently(_student_id uuid)` — تفكّ الارتباطات في الجداول غير المتتالية ثم تحذف صف الطالب.
- كل دالة تتحقق أولاً أن دور المنفذ `manager` أو `secretary` عبر `get_staff_role(auth.uid())` وترفض غير ذلك، مع `search_path = public` و`REVOKE EXECUTE FROM anon` و`GRANT EXECUTE TO authenticated`.
- الجداول التي لا تحمل حذفًا متتاليًا وتحتاج معالجة يدوية قبل حذف الطالب: `attendance_audit_log`, `program_quiz_results`, وتصفير `converted_student_id` في `enrollment_requests` و`pre_registrations`.
- كل عملية تُسجَّل في `admin_audit_log` (المنفّذ، النوع، معرف الطالب، أعداد السجلات المحذوفة).
- الواجهة: تعديل `src/pages/InactiveStudents.tsx`، `src/pages/StudentProfile.tsx`، وإضافة مكوّن حوار مشترك للتأكيد وعرض المعاينة، وتسجيل الصلاحيات في `src/lib/permissionsRegistry.ts`.
